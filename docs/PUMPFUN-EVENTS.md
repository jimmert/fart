# pump.fun Anchor events: layouts used by `fart/chain/events.py`

**Status: UNVERIFIED against mainnet.** The build sandbox had no outbound network, so the layouts
below come from the published pump.fun IDL history and the fixtures under `tests/fixtures/` are
synthetic (generated by `tests/fixtures/gen_fixtures.py` from these same layouts). The
discriminators are computed by the Anchor formula and match the base64 prefixes that are commonly
seen in pump.fun logs (`G3KpTd7rY3Y=` for CreateEvent, `vdt/007mYe4=` for TradeEvent).

Verify on the VPS on day one (section "Verification"), then replace this status line.

## Where events live in a transaction

* `meta.logMessages`: lines `Program data: <base64>` (Anchor `emit!`). This is what
  `logsSubscribe` delivers.
* Self-CPI inner instructions (Anchor `emit_cpi!`): instruction data = 8 bytes
  `e445a52e51cb9a1d` (Anchor's EVENT_IX_TAG, little-endian) + the same event payload. Only visible
  through `getTransaction` (`meta.innerInstructions[].instructions[].data`, base58).

`fart.chain.events.decode_event_bytes` accepts both forms; `fart.chain.tx.events_from_transaction`
reads both and collapses duplicates. If pump.fun emits an event only via CPI, the log stream will
not see it; the signature sweep + `getTransaction` backfill still does.

## Payload = discriminator (8 bytes) + Borsh fields

Discriminator = `sha256("event:<Name>")[:8]`.

| event | discriminator (hex) | base64 prefix |
|---|---|---|
| CreateEvent | `1b72a94ddeeb6376` | `G3KpTd7rY3Y=` |
| TradeEvent | `bddb7fd34ee661ee` | `vdt/007mYe4=` |
| CompleteEvent | `5f72619cd42e9808` | `X3JhnNQumAg=` |
| CompletePumpAmmMigrationEvent | `bde95db95c94ea94` | (computed) |

Borsh encodings: `string` = u32 little-endian length + UTF-8 bytes; `pubkey` = 32 bytes;
`u64`/`i64` = 8 bytes little-endian; `bool` = 1 byte.

## Tolerance rules

Fields are parsed in order until the bytes run out. Fewer than the required fields →
`Undecoded(reason="truncated_or_drift")`, stored in `raw_undecoded` (max 500 per hour) and counted
in `kv decode.*`. A `timestamp` outside 2020–2100 marks the event `suspect` (decoded, but its
timestamp is not used as chain time). Unknown discriminators are stored and counted; known but
irrelevant events (`SetParamsEvent`, `CollectCreatorFeeEvent`, ...) are counted only.
`DecodedEvent.layout` reads like `CreateEvent/full/12of12` or `TradeEvent/partial/10of21`.

## Verification (do this at deploy)

1. Take a fresh create signature from `fart status`-adjacent data:
   `sqlite3 /opt/fart/data/fart.db "select signature from coins where signature is not null order by received_at desc limit 1"`.
2. Fetch it: `curl -s $RPC_HTTP_URL -X POST -H 'content-type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"getTransaction","params":["<sig>",{"encoding":"jsonParsed","maxSupportedTransactionVersion":0}]}' > tx_create_real.json`
3. Decode it with our code:
   ```
   /opt/fart/venv/bin/python - <<'EOF'
   import json
   from fart.chain.tx import events_from_transaction, create_from_tx
   tx = json.load(open("tx_create_real.json"))["result"]
   te = events_from_transaction(tx)
   for e in te.events: print(e.layout, e.suspect, e.extra_bytes)
   for u in te.undecoded: print("UNDECODED", u.reason, u.discriminator_hex)
   print(create_from_tx(te))
   EOF
   ```
   Expect `CreateEvent/full/...` with zero `extra_bytes` and no suspect flags, and a `TradeEvent`
   when the creator bought in the same transaction.
4. Repeat for a migration signature (`migrations.signature`).
5. Copy the two responses to `tests/fixtures/tx_create_real.json` and
   `tests/fixtures/tx_migration_real.json` (public data, no secrets): `tests/test_events.py`
   picks them up automatically and asserts they decode fully.
6. Update the status line at the top of this file and `docs/UNVERIFIED.md`.
